# go-nx 线上协议

- 状态：规范与实现一致；每一处字节布局都有对应的向量测试（`internal/proto/*_test.go`、`internal/remote/versions_test.go`）。
- 版本：控制协议有两个版本，**v0**（ALPN `go-nx`，冻结）和 **v1**（ALPN `go-nx/1`）。屏幕更新流两个版本完全相同。
- 约定：多字节整数一律**小端**；`u8/u16/u32/u64` 是无符号，`i32` 是有符号；字符串是 UTF-8。
- 实现状态以 [`IMPLEMENTED.md`](IMPLEMENTED.md) 为准；设计文档里提过但没有实现的内容不在这里。

## 1. 总览

- 传输：QUIC（quic-go）+ TLS 1.3。主机默认监听 UDP 7000。
- 一个会话 = 一条 QUIC 连接，包含：
  - **一条控制双向流**：由查看器（控制端）打开，承载查看器的 Hello / Ack / Input / Text，以及主机的 Receipt / Welcome。
  - **每个画面更新一条单向流**：由主机打开，写完即关闭（见第 5 节）。
- 信任：自签证书。查看器固定主机指纹（首次连接要用户核对），主机按指纹、密码或配对码决定是否放行（见 `IMPLEMENTED.md` 第 4 节）。这部分不属于线上格式。
- 时限与保活：QUIC 空闲超时 45 s，保活 5 s；主机在收到控制流后 10 s 内必须收到 Hello，否则放弃。

## 2. 版本协商

版本由 TLS 握手里的 **ALPN** 决定，没有额外的往返：

| 主机提供 | 查看器提供 | 结果 |
|---|---|---|
| `go-nx/1`, `go-nx` | `go-nx/1`, `go-nx` | **v1** |
| `go-nx/1`, `go-nx` | `go-nx`（0.3.x 及更早的查看器、NightDesk 查看器） | v0 |
| `go-nx`（0.3.x 及更早的主机） | `go-nx/1`, `go-nx` | v0 |
| `go-nx` | `go-nx` | v0 |

主机按自己的优先级选择（先 `go-nx/1`）。**两边都不需要知道对方的版本号**，也不会因为对方旧而失败。

升级规则：

- 给 v1 **加字段 / 加消息类型 / 加能力位**不需要新 ALPN（见第 4 节的前向兼容规则）。
- 只有**改变已有字段的含义、改变帧结构、或去掉旧行为**才需要新 ALPN（`go-nx/2`），并且主机必须同时继续提供旧的。
- v0 **冻结**：不再改动，只有 NightDesk 已经在发送的两个扩展（第 3 节）被正式收入。

## 3. 控制流 v0

每条消息是 `type u8` 后面跟**固定长度**的字段，没有长度前缀。遇到未知类型，接收方只能结束会话（这是 v1 存在的原因）。

查看器 → 主机：

| type | 名称 | 字段 | 字节数 |
|---|---|---|---|
| `0x01` | Hello | `pwLen u8`, 密码（`pwLen` 字节，可空） | 2 + pwLen |
| `0x02` | Ack | `seq u32` | 5 |
| `0x03` | Input | `opID u64`, `kind u8`, `x i32`, `y i32`, `arg i32` | 22 |
| `0x04` | Text | `opID u64`, `len u16`, UTF-8 文本（`len` ≤ 1024） | 11 + len |

主机 → 查看器：

| type | 名称 | 字段 | 字节数 |
|---|---|---|---|
| `0x81` | Receipt | `opID u64`, `status u8` | 10 |

`Text`（`0x04`）和输入种类 `7`（横向滚轮）是 NightDesk 查看器已经在发送的 v0 扩展。**0.3.x 及更早的 go-nx 主机不认识 `0x04`，收到就结束会话**；输入种类 `7` 只会得到 `Failed` 回执。

示例（v0 Hello，密码 `pw`）：`01 02 70 77`。示例（v0 Text，opID 1，"héllo"）：

```
04 | 01 00 00 00 00 00 00 00 | 06 00 | 68 C3 A9 6C 6C 6F
```

## 4. 控制流 v1

每条消息是一个**帧**：

```
type u8 | length u32 | payload [length]
```

接收方规则（这就是前向兼容的全部机制）：

1. `length` 大于 **16 KiB** → 协议错误，结束会话。检查发生在分配内存**之前**。
2. **未知的 type → 读掉 payload 并忽略。**
3. 已知 type 的 payload **比必需字段短** → 协议错误。
4. 已知 type 的 payload 在必需字段之后**还有多余字节 → 忽略**（以后的版本可以在末尾追加字段）。

查看器 → 主机（type 值与 v0 相同）：

| type | 名称 | payload |
|---|---|---|
| `0x01` | Hello | `version u16`, `caps u64`, `pwLen u8`, 密码, `nameLen u8`, 名字（≤ 64 字节） |
| `0x02` | Ack | `seq u32` |
| `0x03` | Input | `opID u64`, `kind u8`, `x i32`, `y i32`, `arg i32`（21 字节） |
| `0x04` | Text | `opID u64`, 其余全是 UTF-8 文本（≤ **4096** 字节） |

主机 → 查看器：

| type | 名称 | payload |
|---|---|---|
| `0x81` | Receipt | `opID u64`, `status u8` |
| `0x82` | Welcome | `version u16`, `caps u64`, `w u16`, `h u16`, `nameLen u8`, 名字（≤ 64 字节） |

- **Hello** 的 `version` 是查看器会说的最高控制协议版本（现在是 1）；`name` 是查看器的显示名（电脑名），供主机的列表使用，可以为空。非法 UTF-8 被替换为 U+FFFD。
- **Welcome** 由主机在放行查看器之后、发出第一个画面之前发送，**恰好一次**。`caps` 是主机能做的事；`w`、`h` 是被共享屏幕的尺寸（每个画面也带自己的尺寸，以画面为准）。被拒绝的查看器收不到 Welcome，连接以应用层关闭码结束。
- 查看器**只能使用主机在 Welcome 里声明的能力**：没有声明 `CapText` 就不能发 Text。老主机收到不认识的东西会结束会话，这条规则就是为了不发生这种事。

### 能力位（`caps`）

| 位 | 名称 | 含义 |
|---|---|---|
| 0 | `CapText` | 主机能注入 Unicode 文本（`Text` 消息） |
| 1 | `CapWheelH` | 主机理解横向滚轮输入种类 |
| 2 | `CapResize` | 画面尺寸可能在会话中改变（查看器必须按每个画面头里的尺寸重建缓冲）。主机的屏幕源能刷新时声明 |
| 3 | `CapCursor` | 主机能把鼠标指针画进画面。**在 Hello 里带这一位表示"请画"**；主机只对要求的查看器画，v0 查看器永远不画 |

未知位必须忽略。Windows 主机的屏幕源支持刷新和画指针，所以会声明 `CapResize` 和 `CapCursor`。

### 示例

v1 Hello（版本 1，caps 0，密码 `pw`，名字 `PC-1`）：

```
01 | 12 00 00 00 | 01 00 | 00 00 00 00 00 00 00 00 | 02 70 77 | 04 50 43 2D 31
```

v1 Welcome（版本 1，caps = Text|WheelH，1920×1080，名字 `H`）：

```
82 | 10 00 00 00 | 01 00 | 03 00 00 00 00 00 00 00 | 80 07 | 38 04 | 01 48
```

## 5. 画面更新流（v0 / v1 相同）

主机为每个画面更新打开一条单向流，写入后关闭。流的内容：

```
seq u32 | w u16 | h u16 | tile 记录 ...（直到流结束）
```

- `seq` 单调递增。查看器丢弃 `seq` 不大于已应用的更新（被取消或重复的）。
- `w`×`h` 必须满足：两边都 > 0，每边 ≤ **16384**，面积 ≤ **2²⁵** 像素（8K 在内）。越界是协议错误，查看器结束会话。
- 一条 **tile 记录**：`tx u16 | ty u16 | type u8 | len u32 | payload`。tile 边长 **64** 像素，右、下边缘的 tile 可能更小。每个 tile 在一个更新里**至多出现一次**；记录数超过 tile 总数是协议错误。

| type | payload |
|---|---|
| `0` solid | 4 字节：整块的颜色 |
| `1` palette | `n-1 u8`（调色板项数减一）、`n × 4` 字节调色板、RLE 对 `(run-1 u8, index u8)` 直到 payload 结束；展开后必须恰好填满这个 tile |
| `2` raw | DEFLATE 压缩的原始像素；解压结果必须恰好是 `w×h×4` 字节，解压器最多读这么多 |

- **像素格式**：BGRA，自上而下，每像素 4 字节。**第 4 个字节没有定义**——GDI 不保证它是 alpha（在 GitHub 的 `windows-latest` 上恰好是 255，不能当契约）。渲染方必须丢弃它或置为 255，不要把它当透明度。
- 流量控制：主机一次只让一个更新在途。查看器应用一个更新后发 `Ack(seq)`；主机在超时（`1 s + 大小 / 250 KB/s`）内没收到就取消那条流，把它的 tile 并进下一个更新（用最新的屏幕内容重新编码）。所以慢链路降低帧率而不是堆积延迟。
- 查看器 15 s 内一个字节都收不到的更新流会被放弃；单个更新流不得超过 132 MiB（`2²⁵` 像素 × 4 字节 + 4 MiB 余量）。

## 6. 输入

`Input` 的 `kind`：

| kind | 含义 | `arg` |
|---|---|---|
| 1 | 鼠标移动 | — |
| 2 | 鼠标按下 | 0 左，1 右，2 中 |
| 3 | 鼠标抬起 | 同上 |
| 4 | 竖直滚轮 | 以 1/120 格为单位，正值为远离用户 |
| 5 | 按键按下 | Windows 虚拟键码；`0x100` 位表示扩展键 |
| 6 | 按键抬起 | 同上 |
| 7 | 横向滚轮 | 以 1/120 格为单位，正值为向右 |

- **坐标** `x`、`y`：被共享屏幕上的像素，原点在该屏幕左上角，主机夹到屏幕范围内。**除移动外，按下 / 抬起 / 滚轮也各自携带坐标**，不依赖上一次移动。
- **`NoMove`**（`-2³¹`）：鼠标按下 / 抬起 / 滚轮的 `x` 和 `y` **同时**为它，表示"就在指针现在的位置执行，不要先移动"。主机自己在查看器断开后替它松开按键时用，避免把指针拖回当初按下的位置；查看器正常发送的事件总是带真实坐标。
- **opID**：非零 = 需要回执；主机对同一个 opID 只执行一次（保留最近 1024 个），重发只会重发回执，用来在丢失回执时安全重试。**opID 0 = fire-and-forget**（不去重、没有回执），用于鼠标移动和按键自动重复。
- **回执** `status`：`1` Executed，`2` Failed。
- **持有的输入**：查看器断开或被顶替时，主机释放该会话按下的键和鼠标键；一个已被顶替的旧会话不能再输入。
- **文本**：`Text` 以 Unicode 直接注入，不依赖主机的键盘布局和输入法状态。同样有 opID 去重和回执。非法 UTF-8 在进入注入器之前被替换。

## 7. 会话与关闭码

- 同时只有一个控制者；新的、已放行的连接顶替旧的（旧的收到 `3`）。
- 主机拒绝或结束连接时用 **QUIC 应用层关闭码**说明原因：

| 码 | 含义 |
|---|---|
| 1 | 未配对，且没有提供有效的密码 / 配对码 |
| 2 | 密码或配对码错误 |
| 3 | 被另一个查看器顶替 |
| 4 | 错误次数过多，稍后再试 |
| 5 | 这台设备已从主机的配对列表中移除 |
| 6 | 正在等待认证的连接太多，稍后再试 |
| 7 | 主机切回了严格模式，而这个会话没有经过验证 |

## 8. 限制汇总

| 项 | 限制 |
|---|---|
| v1 控制帧 payload | ≤ 16 KiB |
| 文本 | v0 ≤ 1024 字节；v1 ≤ 4096 字节 |
| 名字（查看器 / 主机） | ≤ 64 字节 |
| 密码 / 配对码 | ≤ 255 字节 |
| 画面尺寸 | 每边 ≤ 16384，面积 ≤ 2²⁵ 像素 |
| 一个更新里的 tile 记录 | ≤ tile 总数 |
| 等待认证的连接 | 总数 ≤ 16，同一 IP ≤ 4 |
| 去重缓存 | 最近 1024 个 opID |

## 9. 兼容矩阵

| | v0 主机（0.3.x 及更早的 go-nx） | v0 + 扩展的主机（现在的 go-nx 在 v0 下；NightDesk 主机） | v1 主机（现在的 go-nx） |
|---|---|---|---|
| **v0 查看器**（0.3.x 及更早的 go-nx） | v0 | v0 | v0 |
| **NightDesk 查看器**（v0 + Text + 横向滚轮） | v0；Text 会结束会话，横向滚轮得到 Failed | v0 | v0，Text 和横向滚轮都可用 |
| **v1 查看器**（现在的 go-nx） | v0；`SendText` 返回 `ErrUnsupported` | v0；同上，除非调用者用 `AssumeCaps` 担保 | **v1**，能力来自 Welcome |

NightDesk 一侧要采用 v1 之前，不需要改动就能继续连 go-nx 主机；这一点由 `TestFrozenV0ViewerAgainstTheCurrentHost` 用手写字节固定下来。
