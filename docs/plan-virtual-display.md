# 计划：画质放大 + 按主控端分辨率的虚拟显示器（2026-10-29）

**状态：已实现并随 0.9.0 发布，真机未验证（`ACCEPTANCE.md` H38）。实现与偏差见 `handoff-2026-10-29-virtual-display.md`。**

## 用户要求与决定

> 能否添加选项允许使用主控端的分辨率进行显示渲染（相当于一个由主控端管理的新的虚拟显示器）或者提供upscale分辨率的算法？

用户选择：①**虚拟显示器用 Parsec VDD**；②**go-nx 内置签名安装包，缺驱动时安装**。画质放大无论如何都做。

参考（只读）：NightDesk 的 `VddClient.cs`、`VddInstaller.cs`、`DisplayController.cs`、`DisplayTopology.cs`、`NativeDisplays.cs`。

## 1. 画质放大（只改主控端）

- 现状：`session.draw` 放大用最近邻、缩小用双线性。非整数倍放大时像素粗细不均、锯齿明显；大幅缩小时双线性会丢细节（文字发虚、闪烁）。
- 做法：Kage 着色器（Ebiten 自带，无新依赖）。
  - 放大：Catmull-Rom 双三次（16 次取样），再加一点对比度自适应锐化（CAS 思路），边缘清楚但不过冲。
  - 缩小：按每个屏幕像素覆盖的源像素范围做面积平均（最多 8×8 取样），文字不闪。
  - 整数倍 100%：原样复制。
- 设置 → 会话 → "画面缩放"：清晰（默认，上面的算法）/ 平滑（双线性）/ 像素（最近邻）。
- 测试：GPU 测试（Xvfb 与 Windows 运行器）验证着色器能编译、颜色不越界、边缘比双线性更锐、整数倍时与原图一致。

## 2. 协议

- 新能力位 `CapVirtualDisplay`（bit 4）：主机允许并且有 Parsec VDD 时才声明。
- 查看器 → 主机 `V1ViewSize`（0x05）：`W u16, H u16`（设备像素）。`0×0` 表示不要虚拟屏。窗口大小变化时发送（防抖 0.5 s）。
- 主机 → 查看器 `V1DisplayState`（0x83）：`Virtual u8, W u16, H u16, Message string`：当前是否在虚拟屏上、用的分辨率、失败原因。
- 未知类型照旧跳过，NightDesk 已发布的客户端不受影响。规范写进 `docs/protocol.md`。

## 3. 主机：虚拟显示器

- `internal/vdisplay`：
  - 可移植部分（Linux 上测试）：选模式（驱动支持的模式里，放得进请求尺寸的最大的那个，同面积优先 60 Hz；都放不进就取最小的）；显示拓扑快照的校验；**管理器状态机**（创建 / 换分辨率 / 恢复的先后顺序，用假的系统接口测）。
  - Windows 部分：Parsec VDD 客户端（设备接口 `{00b41627-04c4-429e-a26e-0265cf50c8fa}`，IOCTL 加 / 删 / 保活 / 版本，保活每 100 ms），找到新建的 `\\.\DISPLAYn`，设模式（`ChangeDisplaySettingsEx`，先测试再应用），拓扑快照与"只保留虚拟屏"（`QueryDisplayConfig` / `SetDisplayConfig`）。
- 顺序（防止截屏对象丢失显示器）：建虚拟屏 → 设模式 → 截屏切到虚拟屏 → 存恢复快照到磁盘 → 只保留虚拟屏。恢复反过来：按快照恢复拓扑 → 截屏切回原显示器 → 删虚拟屏 → 删快照。
- 何时恢复：查看器发 0×0、会话结束、主机换地址、go-nx 退出。go-nx 崩溃时 VDD 收不到保活会自己删掉虚拟屏；下次启动发现磁盘上的快照就先恢复。
- 拒绝的情况：RDP 会话里；没有活动的物理显示器；ParsecVDisplay 正在运行（两个管理器会抢）。
- 设置 → 共享 → "虚拟显示器"：驱动状态、安装按钮、"允许主控端按它的窗口大小使用虚拟显示器"（默认关）。

## 4. 驱动安装

- `parsec-vdd-0.45.0.0.exe`（517256 字节，SHA-256 `e23332448fdaf5aa017cb308db5ef6855fac526a7ded05d80c039404126d5362`，签名主体 Parsec Cloud, Inc.）随 go-nx 嵌入。
- 安装前核对大小、SHA-256 与 Authenticode 签名（`WinVerifyTrust`），解到 `%LocalAppData%\go-nx\driver\`，`runas` + `/S` 静默安装，等它退出后重新探测。
- **UAC 确认框在安全桌面上，go-nx 远程看不到也点不了**：安装要在主机前确认（或用能处理 UAC 的工具，如 RustDesk 服务模式）。界面上写明。

## 5. 主控端

- 会话工具条加"匹配窗口分辨率"开关（主机声明了 `CapVirtualDisplay` 才出现）；设置 → 会话里设默认值。
- 打开后发送视口大小；窗口改变时再发；关掉发 0×0。工具条显示主机回的状态（在虚拟屏上 / 原因）。

## 验证边界

GitHub 的 Windows 运行器没有 Parsec VDD，虚拟屏、拓扑切换只能在真机上验证（`ACCEPTANCE.md`）。能自动化的：选模式、快照校验、状态机顺序、协议编解码、安装包哈希、着色器。
