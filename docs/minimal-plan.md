# go-nx 最小方案(定稿)

> **这是设计意图，不是实现状态。** 例如 tile 差分实际用 `bytes.Equal` 而非 xxHash64，编码用 flate 而非 LZ4，配对没有 6 位码。以代码为准的清单见 [`IMPLEMENTED.md`](IMPLEMENTED.md)。

目标:Win10/Win11 之间的轻量、可靠、抗网络波动的远程查看与操作。帧率低可接受。

## 技术选择
- 语言:纯 Go,无 cgo、无 C++ shim。
- 采集:GDI BitBlt 整屏抓取(syscall 调 user32/gdi32),默认 5–10 fps。
- 传输:QUIC(quic-go),单连接。
- 客户端:Go 原生窗口(Gio 或 Ebiten),单 exe。
- 被控端:单 exe,普通权限运行。

## 数据流
1. 主机定时抓屏,切 64×64 tile,与上一帧逐 tile 哈希(xxHash64)比对。
2. 只编码变化 tile:单色 / 调色板+RLE / LZ4 原始,无损。
3. 每个更新帧用一条独立的单向 QUIC 流发送;若新帧产生时旧帧仍未发完,取消旧流。
   发送端合并被取消帧的脏 tile,保证客户端最终画面一致,弱网只掉帧、不堆积延迟。
4. 客户端发送输入:一条可靠双向流,每个事件带 opId。
5. 主机用 SendInput 注入;维护最近 1024 个 opId 的去重缓存,重复 opId 只回原回执,不重复执行。
6. 客户端 3 s 未收到回执只提示"不确定",不自动重试。

## 配对与安全
- 手填 IP:端口,首次连接输入主机显示的 6 位码。
- QUIC/TLS 1.3,自签证书,双方保存对端指纹(TOFU);指纹变化则拒绝。
- 无权限分级:配对成功即可操作。

## 明确不做
mDNS 发现、二维码/离线配对、审计日志、剪贴板/文件、多屏选择、view/control 分级、国密、
视频编码、DATAGRAM/FEC、自定义拥塞控制、Windows 服务、驱动、旁路程序、Win7/8。

## 已知边界
- UAC/安全桌面/登录界面不可见。
- 目标窗口设置 WDA_EXCLUDEFROMCAPTURE 时画面为黑。
- GDI 对独占全屏 DirectX 内容可能抓不到,需现场验证;若不行再换 DDA。

## 里程碑
- M1:主机抓屏 + tile 差分 + 编码,客户端本机回环显示。
- M2:QUIC 传输、取消旧帧、输入注入、opId 去重。
- M3:配对码 + 指纹校验;用 netem 在 1 Mbps / 80 ms / 1% 丢包下验证可操作、无重复执行。

## 验收
1. 远端改参数并保存,结果与本地一致。
2. 弱网下重复发送同一 opId,主机只执行一次。
3. 界面静止时码率接近 0。
4. 12px 小字逐像素一致。
