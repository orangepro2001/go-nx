# 工控远程控制方案 —— 最终收敛版

| 项目 | 内容 |
|---|---|
| 版本 | v3.0（取代 v1.0 报告与 v2.0 收敛方案） |
| 日期 | 2026-10-24 |
| 目标软件 | Pixel Inspector（Pixel Vision Inspection System）等 Windows 桌面工控 HMI |
| 平台 | 被控端与主控端均为 Windows 10 1809+ / Windows 11，x64；**不支持 Windows 7/8.x** |
| 部署 | 局域网 P2P，无中心服务器；**不装旁路程序、不挂钩、不装内核驱动** |

---

## 1. 目标与范围

### 1.1 目标
对现场工控 Windows 软件进行**远程查看与操作**，核心场景：
- 参数调整（Specification / Light / Mask / Chain / 阈值表）；
- 按钮操作（移动、保存、调光、输送机、检查、自动/手动切换等）；
- 结果查看（缺陷数、热力图、日志）。

### 1.2 非目标
- 不做游戏/视频级流畅远控；
- 不读取目标软件内部数据、PLC 变量、控件属性；
- 不做多会话/虚拟桌面；
- 不做安全桌面（UAC、登录界面、Ctrl+Alt+Del 之后的界面）的直接可见控制；
- 不做 Linux/macOS/移动端。

### 1.3 成功标准（MVP 验收）
1. 参数修改：点击参数框 → 输入数字 → 保存，全程远端可完成，结果与本地一致；
2. 按钮确认：点击后有可见状态反馈，**不会因网络延迟重复执行**；
3. 小字保真：参数表、状态色、图标在远端 1:1 显示时与本地逐像素一致（无损模式）；
4. 静止码率：界面无变化时 ≤ 5 kbps；
5. 输入回显：P95 ≤ 100 ms（局域网）。

## 2. 架构总览

```
被控端 Host（Win10/11 x64，单 exe，普通权限运行，无驱动）
 ├─ 采集      DXGI Desktop Duplication（主）｜ WGC（单窗口，可选）
 ├─ 变化检测  64×64 tile 哈希 → 脏 tile 集合
 ├─ 编码      无损 tile（调色板 + RLE + LZ4）
 ├─ 输入注入  SendInput（绝对坐标映射，多屏虚拟桌面坐标）
 ├─ 指令处理  幂等 ID + 回执 + 超时
 └─ 传输      QUIC 单连接，多条可靠流

主控端 Client（同平台）
 ├─ 解码 → D3D11 呈现（1:1 或整数倍最近邻缩放）
 ├─ 输入采集 → 指令（带幂等 ID）
 └─ 发现与配对（同一套 Host 通道）

局域网发现：mDNS；手动 IP；二维码/离线配对包
```

### 2.1 进程与部署
- 被控端：`nsu-host.exe`，单文件，以普通用户会话进程运行，开机自启可选（计划任务，非服务）；
- 主控端：`nsu-client.exe`，单文件；
- 不注册系统服务、不安装驱动、不修改目标软件目录、不注入进程。

### 2.2 为何 DDA 足以覆盖目标界面
目标软件为普通 Win32/WPF 类桌面窗口，内容由 DWM 合成，DDA 可获取完整桌面帧与脏矩形，无需访问目标进程。

## 3. 功能设计

### 3.1 采集与变化检测
| 项 | 设计 |
|---|---|
| 主路径 | DDA 全屏/单屏采集，获取 dirty rect 与 move rect |
| 辅路径 | WGC 单窗口（当需要只授权某窗口时） |
| 脏区处理 | 脏矩形外扩到 64×64 tile 边界 → 逐 tile xxHash64 比对 → 变化 tile 进入编码队列 |
| 校验 | 每 N 秒（默认 5 s）对一个随机 tile 子集做全量校验，检测 DDA 漏报；不一致则强制该区域全量重传并记录告警 |
| 设备丢失 | `DXGI_ERROR_ACCESS_LOST` 时自动重建采集会话，最多 3 次指数退避，失败则上报错误并保持最后画面 |

### 3.2 编码
- **唯一编码路径：无损 tile**（不引入视频编码、不引入有损 JPEG）；
- tile 类型：SOLID（单色）、PALETTE（≤256 色，调色板 + RLE）、RAW（其它，LZ4）；
- 帧级：多个 tile 打包进一个 QUIC 流帧，按 tile 序号排序；
- 全屏切换（如切换页签）时允许一次性全量 tile，体积约 200–800 KB，可接受。

### 3.3 传输（QUIC）
| 流 | 方向 | 内容 | 可靠性 | 优先级 |
|---|---|---|---|---|
| S0 控制 | 双向 | 版本协商、配对、能力、心跳、关闭 | 可靠 | 高 |
| S1 输入 | 客户端→主机 | 鼠标/键盘/文本输入事件，带幂等 ID | 可靠 | 最高 |
| S2 回执 | 主机→客户端 | 输入事件的执行结果（成功/失败/超时） | 可靠 | 最高 |
| S3 画面 | 主机→客户端 | tile 更新帧 | 可靠（不使用 DATAGRAM） | 中 |
| S4 剪贴板/文件 | 双向 | 可选，限速 | 可靠 | 低 |

- 不使用 QUIC DATAGRAM，不做自研 FEC；丢包由 QUIC 重传；
- 拥塞控制使用 quic-go 默认实现；
- 连接迁移依赖 QUIC 原生能力（Wi-Fi/有线切换不断线）；
- TLS 1.3 + 证书指纹配对（TOFU）。

### 3.4 输入与指令
- 每个输入事件带 `opId`（UUID）与 `clientTs`；
- 主机维护最近 N=1024 个 `opId` 的去重缓存，重复 `opId` 直接回执原结果，**不重复执行**；
- 回执状态：`ACCEPTED` / `EXECUTED` / `FAILED(reason)` / `TIMEOUT`；
- 超时：默认 3 s 无 `EXECUTED` 则客户端提示“不确定，请查看画面”，**不自动重试**；
- 键盘：传递扫描码 + 修饰键状态；文本输入使用 `KEYEVENTF_UNICODE`；
- 鼠标：绝对坐标映射到虚拟桌面，多屏时按主机实际分辨率换算；
- 禁止组合键：`Ctrl+Alt+Del`、`Win+L` 等由主机拒绝并回执 `FAILED(SECURE_DESKTOP)`。

### 3.5 发现与配对
| 场景 | 机制 |
|---|---|
| 同网段 | mDNS `_nsu._udp.local` 广播（名称、指纹前缀、端口） |
| 手动 | 输入主机 IP:端口 |
| 首次配对 | 主机显示 6 位配对码 + 证书指纹，客户端输入确认；成功后双方保存指纹 |
| 后续连接 | 证书指纹校验，指纹变更则拒绝并提示 |
| 权限 | 每个客户端可设 `view`（只看）或 `control`（可操作）；默认 `view` |

### 3.6 显示与交互（客户端）
- 默认 1:1 显示，可切换整数倍最近邻缩放，禁止默认双线性；
- 光标：本地预渲染，服务端光标位置低频校正；
- 多屏：可选择显示哪个主机屏幕；
- 输入回显：客户端在按下后立即显示按压反馈，结果以回执为准。

## 4. 性能指标（SLO）

| 编号 | 指标 | 目标 | 测试条件 |
|---|---|---|---|
| S1 | 静止码率 | ≤ 5 kbps | 1080p，界面无变化 60 s |
| S2 | 参数修改一次（点击+输入+保存）峰值码率 | ≤ 60 kbps，持续 < 1 s | 同上 |
| S3 | 输入回显 P95 | ≤ 100 ms | 千兆 LAN |
| S4 | 图像区动态刷新 | ≤ 2 Mbps，10–15 fps | CALIBRATE 相机图局部刷新 |
| S5 | 全屏切换（页签切换）完成时间 | ≤ 500 ms（LAN） | 1080p |
| S6 | 文本逐像素保真 | 100% | 无损模式 |
| S7 | 主机 CPU（稳态） | ≤ 3% 单核 | i3 级 CPU，静止/操作 |
| S8 | 主机内存 | ≤ 150 MB | 1080p 单屏 |
| S9 | 弱网可用性 | 1 Mbps / 80 ms / 1% 丢包下操作可完成，无重复执行 | netem |

## 5. 安全

| 项 | 设计 |
|---|---|
| 传输加密 | QUIC/TLS 1.3 |
| 身份 | 证书指纹 + 首次配对码 |
| 授权 | `view` / `control` 两级；可按连接设置超时 |
| 审计 | 记录连接时间、客户端指纹、输入事件类型与 opId（不记录输入的敏感数字内容，可配置） |
| 本地确认 | 首次配对与权限提升需主机端本地确认（弹窗） |
| 最小权限 | 普通用户运行，不请求管理员权限 |

## 6. 能力边界（需向客户明示）

1. **UAC 提权弹窗、安全桌面、登录界面**：不可见、不可操作。遇到时需现场人员处理，主机返回 `FAILED(SECURE_DESKTOP)`。
2. **被控软件若设置了屏幕捕获保护**（`WDA_EXCLUDEFROMCAPTURE`）：采集结果为黑色，需停用该保护或改用整屏模式。
3. **独占全屏 DirectX 程序**：DDA 可捕获，但需确认现场测试。
4. **Win10 22H2 已于 2025-10 停止支持**：推荐 Win10 LTSC 2021 / IoT LTSC 2021 或 Windows 11。
5. **不能读取软件内部数据**：所有操作依赖屏幕像素，参数校验只能看屏幕显示值。
6. **不做多人同时操作**：同一时间仅一个 `control` 连接，其余为 `view`。

## 7. 实现路线与验收

### 7.1 阶段计划（约 7 个月到 v1.0）

| 阶段 | 周期 | 内容 | 验收门禁 |
|---|---|---|---|
| P0 基线 | 2 周 | 在 Win10/Win11 与 Pixel Inspector 测试机上，测 RDP、TigerVNC、RustDesk 作为对照 | 确认 tile 方案相对基线的码率优势 ≥ 40% |
| P1 采集编码 | 6 周 | DDA 采集、tile 哈希、无损编码、本地回环 | S1、S2、S6 通过 |
| P2 传输输入 | 6 周 | QUIC 多流、输入幂等、回执、netem 测试 | S3、S9 通过 |
| P3 发现配对 | 4 周 | mDNS、配对码、权限、审计 | 配对/权限用例通过 |
| P4 硬化 | 6 周 | 采集异常恢复、长时间运行、单 exe 打包 | 72 h 连续运行无崩溃 |
| P5 现场试点 | 4 周 | 3 个真实现场，记录问题与性能 | 试点验收单 |

### 7.2 MVP 验收用例（核心 6 条）
1. 远端修改 Light-1 亮度数值并保存，本地读取一致；
2. 远端点击“移动”按钮，回执 `EXECUTED`，画面状态正确；
3. 网络抖动下重复发送同一 `opId`，主机仅执行一次；
4. 参数表 12px 小字与状态色逐像素一致；
5. 界面静止 60 s，码率 ≤ 5 kbps；
6. 切换到 UAC 弹窗时，回执 `FAILED(SECURE_DESKTOP)`，且不崩溃。

## 8. 技术选型

| 领域 | 选择 | 许可 |
|---|---|---|
| 语言 | Go 1.21+（主体）；采集模块可用 C++17 薄 shim | — |
| QUIC | quic-go | MIT |
| 采集 | DXGI DDA（C++ shim 调用） / WGC | Windows API |
| 哈希 | xxHash64 | BSD |
| 压缩 | LZ4 | BSD |
| 发现 | mDNS（hashicorp/mdns 或等价） | MPL/MIT |

**明确不使用**：RustDesk、Sunshine、TigerVNC/TurboVNC、nx-libs（GPL/AGPL 传染风险，且与设计不符）、任何内核驱动、任何 DLL 注入或 API Hook。

## 9. 与 v2 方案的主要差异

| 项 | v2 | v3（本版） |
|---|---|---|
| 视频编码路径 | 保留（硬件 H.264/HEVC） | **移除** |
| 媒体流 | QUIC DATAGRAM + 自研 FEC | **移除，全部可靠流** |
| 自定义 CC | 计划 | **移除，用默认实现** |
| 渐进精化 | 计划 | **移除，v1.1 再议** |
| 旁路程序 | 未明确 | **明确不装** |
| 输入幂等 | 未明确 | **必须（opId + 回执）** |
| 多观众 | 计划 | 仅 `view` 旁观，`control` 单人 |
