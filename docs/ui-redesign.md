# go-nx UI 重设计方案（v2）

- 状态：**仅设计，没有任何界面代码改动**。v1 与 v2 写于 2026-10-28。**U0 技术验证已做**（同日，`docs/ui-baseline.md`），其结果已回写到第 3、4.2、4.3、11、12 节，用 **【U0】** 标出。
- 依据：仓库现状（`internal/ui`、`cmd/go-nx`）、Ebiten v2.10.5 与 quic-go v0.64.1 与 go-text/typesetting v0.3.5 的源码（`~/go/pkg/mod`）、路线图与验收清单。
- 约束来自项目初衷：**少依赖、超高性能**，单个静态 exe，无 cgo。不新增第三方模块。
- 标注：**【事实】** 来自代码或模块源码，可复核；**【推断】** 是我的判断，没有在本项目里实测；**【目标】** 是要达到的数字，不是已测得的数字；**【提议】** 是尚未定的设计选择。所有性能数字必须先过 U0 的基线测量才算数。

## 1. 目标与非目标

目标：

1. **效率第一**：每个设计决定的评判标准是——操作远程电脑时是否更快、更不容易出错、出了问题更容易恢复。外观服务于这一点，不对标任何现有产品。
2. 空闲时几乎不占 CPU/GPU；会话中 UI 不增加每帧工作量。
3. **简体中文、English、한국어** 三语完整支持：界面文案、输入法、字体、换行。
4. 主题色为**蓝色**，深浅两套主题。
5. 布局可缩放，支持 100%–200% 显示缩放，取代现在散落的绝对坐标常量。
6. 每个界面状态在没有 Windows 的 CI 上也能截图比对（三种语言）。

非目标：

- 不引入 Web 技术栈（WebView2、HTML/CSS、Electron）。
- UI 阶段不改线上协议、不新增远控功能；界面需要的后端改动在第 10 节单列，并标明依赖路线图的哪个阶段。
- 不承诺屏幕阅读器支持（第 11 节）。
- 繁体中文、日文的**界面文案**暂不做（字体回退链仍能正常显示这些文字，比如设备名）。

## 2. 现状盘点【事实】

| 项 | 现状 |
|---|---|
| 渲染栈 | Ebiten v2.10.5（Windows 上链接了 DirectX 和 OpenGL 两个后端）+ `text/v2` + go-text/typesetting |
| UI 代码 | `internal/ui`：`home.go` 342 行、`tabbar.go` 102、`ui.go` 109、`logview.go` 54，加上 `cmd/go-nx/viewer_windows.go` 323 行。全是矩形 `Fill` + 文字，**没有**圆角、阴影、图标、动画、主题 |
| 布局 | 固定 1180×700 的绝对坐标常量（`chkY`、`actionY`、`listX` 等）；窗口大小固定，靠 `DeviceScaleFactor` 整体放大 |
| 字体 | 只内嵌 Go Regular（`goregular.TTF`），**只含拉丁字母——现在界面显示不了中文和韩文** |
| 文本输入 | 输入框只处理 `ebiten.AppendInputChars`。Ebiten 在窗口创建后**默认禁用 IME**（`internal/ui/ui_windows.go` 注释 "By default, IME should be disabled (#2918)"），只有 `exp/textinput` 开启文本输入会话时才恢复；go-nx 没用它。所以**现有输入框用不了中文 / 韩文输入法**（来自源码的判断，没有在 Windows 上试过） |
| 换行与截断 | `ui.Wrap` 用 `strings.Fields` 按空白切词，**不含空格的中文句子不会换行**；`ui.Truncate` 按 rune 截断，不管字素簇 |
| 按键 | Ebiten 的 `Key` 枚举里没有 Hangul / Hanja 键（国际键只有 `KeyIntlBackslash`），Windows 键盘映射里也没有相关处理——**한/영 键和한자键无法被转发** |
| 帧循环 | 窗口可见时固定 60 TPS 持续重绘，隐藏到托盘时 5 TPS（`activeTPS`/`idleTPS`）。没有"没变化就不画" |
| 远程画面 | tile 补丁写入一张 `ebiten.Image`，`DrawImage` 缩放绘制；只有"适应窗口"一种显示方式；BGRA→RGBA 的通道交换在 **CPU** 上逐 tile 做（`bgraToRGBA`） |
| 已有但未使用的能力 | `ebiten.SetFullscreen`、`ebiten.SetCursorMode(CursorModeCaptured)` 存在，go-nx 一处都没调用；`quic.Conn.ConnectionStats().SmoothedRTT` 存在，go-nx 没读 |
| 无障碍 | Ebiten 源码里没有 UI Automation / `WM_GETOBJECT` 相关代码 |
| 依赖 | `go.mod` 直接依赖 4 个模块：ebiten、systray、quic-go、x/image；整个模块图 39 个（含本模块）。exe 约 19 MB（大头是 QUIC 和 Ebiten） |

结论：渲染栈本身（GPU 纹理、DrawImage、Kage 着色器）足够好；缺的是**一套 UI 工具箱**、**按需渲染**、**三语排版与输入**，不是换引擎。

## 3. 性能预算【目标，待 U0 基线验证】

| 场景 | 预算 | 怎么测 |
|---|---|---|
| 窗口可见、无动画、无会话（空闲） | 单核 CPU < 0.3%，不提交 GPU 帧。**【U0】** 只有 `FPSModeVsyncOffMinimum` + `ScheduleFrame` 稳定做到（两次运行 0 帧 / 秒、0.000%）；"跳过绘制"在 Windows runner 上 0–2%，Linux 软件 GL 上 2.5% | Windows 性能计数器 / 任务管理器采样 60 s |
| 会话中画面静止 | 无输入、无 tile 更新时不提交帧 | 自己数 `Draw` 次数 |
| 会话中画面更新 | 每帧最多 2 次 `DrawImage`（远程画面 + 缓存好的 UI 叠加层）；一个 64×64 tile 的上传 + 绘制 ≤ 0.2 ms | `testing.B` + 合成源 |
| 主页一帧 CPU 提交时间 | p99 ≤ 2 ms（1080p，100% 缩放） | `testing.B`，N=1000 帧 |
| UI 响应 | 点击到画面变化 ≤ 1 帧（16.7 ms @60Hz） | 输入时间戳到 `Draw` 完成 |
| 启动到第一帧 | ≤ 300 ms（日志已记录 `first Draw`，先量基线）；**启动路径不读取 CJK 字体文件** | `go-nx.log` 的 startup 行 |
| 首次用到某种 CJK 字体 | **【U0 改】** 打开并可用 ≤ 100 ms，**在后台 goroutine 里完成、不阻塞 UI**（实测 Windows：YaHei 100 ms、Malgun 34 ms、Segoe 5 ms）；留在堆里的是文件大小的 1.5–2.2 倍（YaHei 18.8→37 MB，Malgun 12.8→28 MB），**一次只常驻界面语言那一个** | `testing.B` + 进程私有工作集 |
| 切换界面语言 | ≤ 100 ms，无需重启 | 计时 |
| 常驻内存（空闲） | **【U0 改】** 英文界面 ≤ 45 MB，中 / 韩界面 ≤ 80 MB 私有内存，glyph / 文本布局缓存有上限。依据：一个空的 Ebiten 窗口在 Windows 上就是 34 MB 私有 / 44 MB 工作集（软件渲染的 runner；真实 GPU 驱动待在用户 PC 上量），再加界面语言对应的 CJK 字体 28–37 MB。**原来的 60 MB 放不下中 / 韩界面** | 任务管理器私有工作集 |
| 二进制增量 | UI 相关 ≤ 1.5 MB（含三语字符串表；字体不内嵌） | `ls -l build/go-nx.exe` 对比 |
| 新增第三方模块 | 0 | `go.mod` diff |

预算写进 CI：布局和绘制的 benchmark 作为回归门槛，超出基线 20% 就失败（U6）。

## 4. 技术栈决策

### 4.1 选项评估

| 选项 | 新增依赖 | 性能 | 中日韩文本与输入法 | 结论 |
|---|---|---|---|---|
| **A. 继续用 Ebiten，自研极简 UI 层**（推荐） | 0 | 好：远程画面本来就在 GPU 纹理上；UI 叠加层缓存成一张纹理 | 有 `exp/textinput`（实验性）；字体用系统字体 | **选它** |
| B. Gio | 新模块 `gioui.org` 及其依赖 | 好【推断】 | 文本栈同为 go-text【推断】 | 需要替换整个窗口 / 渲染层，远程画面局部上传模型要重做；增加依赖，收益不抵成本 |
| C. Wails / WebView2 | WebView2 运行时 + 前端工具链 | 内存和启动都重 | 好 | 与"少依赖、超高性能"直接冲突 |
| D. 原生 Win32 + Direct2D/DirectWrite（纯 syscall，无 cgo） | 0 第三方，但要手写 COM 调用 | 最好 | 最好（系统 IME / 无障碍） | 工作量最大，没有现成的纯 Go 绑定；**长期备选**，U0 发现 A 的 IME 或稳定性不可接受时再启动 |
| E. libw2k（Win2000 风格） | — | 好 | — | 风格不符，不选 |
| F. Fyne | 多，且常带 cgo | 一般【推断】 | — | 不选 |

B–F 的判断是【推断】，没有在本项目里做过基准；只有 A 的依据来自本仓库代码和 Ebiten 源码。

### 4.2 在现有依赖里要用到的能力【事实：已在源码里核对存在】

- **Kage 着色器**：`ebiten.NewShader`、`DrawRectShader`、`DrawTrianglesShader`。一个 SDF 着色器同时画圆角填充、描边和柔和阴影，相同着色器 + 相同纹理的绘制会被合批。
- **输入法**：`github.com/hajimehoshi/ebiten/v2/exp/textinput`。**实验性，API 可能变**；`Field` 已标 Deprecated，新 API 是 `Composer`（`OnNewSession` 提供 `CaretBounds` 让候选窗跟随光标，`OnComposition` 给出预编辑文本和选区，`OnCommit` 给出提交文本）。Windows 实现走 IMM32（`ImmGetCompositionStringW`、`ImmSetCandidateWindow`、`WM_IME_COMPOSITION`）。模块里附带 `examples/textinput`。
- **多字体回退**：`text/v2` 的 `MultiFace`；`NewGoTextFaceSourcesFromCollection` 能读 `.ttc` 字体集合（`msyh.ttc` 就是）。
- **字体按需读取**：`NewGoTextFaceSource` 收到同时实现 `Read/Seek/ReadAt` 的对象时**直接使用，不读入内存**；否则 `io.ReadAll` 整个文件读进内存（`toFontResource`）。`*os.File` 满足前者（已在编译期验证）。
- **Unicode 断行与字素簇**：go-text/typesetting 的 `segmenter` 包有 `LineIterator`（UAX#14）和 `GraphemeIterator`（UAX#29）。它与 Ebiten 的文本栈同属一个模块，已在模块图里，不是新依赖。
- **矢量路径**：`ebiten/vector`，用来把图标路径栅格化。
- **窗口与光标**：`SetFullscreen`、`SetCursorMode`、`SetCursorShape`、`Monitor().DeviceScaleFactor()`。
- **延迟**：quic-go 的 `Conn.ConnectionStats().SmoothedRTT`。
- **按需渲染**：`ebiten.ScheduleFrame()` 配合 `FPSModeVsyncOffMinimum`。**注意：这个模式在 v2.5 起被标为 Deprecated**（v2.10.5 里仍存在），官方推荐的替代是 `SetScreenClearedEveryFrame(false)` + 没变化就跳过 `Draw`（模块附带 `examples/skipdraw`）。后者省 GPU，但 `Update` 仍按 TPS 运行。**【U0 结果】** （a）弃用的模式在 v2.10.5 上**仍然正常**，Windows/DirectX 和 Linux/OpenGL 都是：不请求时 0 帧 / 秒、0% CPU，每次 `ScheduleFrame()` 恰好引出一帧，延迟 1–2 ms；（b）降级方案（低 TPS + 跳过 `Draw`）也可用但**主循环仍按 60 次 / 秒调用 `Draw`**，Windows runner 上 0–2% CPU，Linux 软件 GL 上 2.5%，达不到最小模式的零。**决定：按需渲染用 `FPSModeVsyncOffMinimum` + `ScheduleFrame()`，封装在一处，降级方案保留。** 该模式下"新的输入"也会触发帧，所以只需在没有输入但画面要变时（连接状态、tile 到达、动画）调用。详见 `ui-baseline.md` ②。

### 4.3 字体策略（三语 + 内存）

原则：**不内嵌 CJK 字体**（会让 exe 增加数 MB，违背初衷），用系统自带字体，按需、按文件打开。

| 用途 | 字体 | 文件【推断，U0 在 `windows-latest` 和你的 PC 上核对】 |
|---|---|---|
| 拉丁字母、数字 | Segoe UI（及 Semibold） | `segoeui.ttf`、`seguisb.ttf` |
| 简体中文 | Microsoft YaHei UI | `msyh.ttc`（字体集合，取 YaHei UI 那一项） |
| 한국어 | Malgun Gothic | `malgun.ttf` |
| 兜底 | Go Regular | 已内嵌 |

- **定位文件**：读注册表 `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Fonts`（以及同名的 `HKCU` 键，覆盖按用户安装的字体）把字体名映射到文件，找不到再拼 `%WINDIR%\Fonts`。用 `golang.org/x/sys/windows/registry`（`x/sys` 已在模块图里，变成直接 import，不新增模块）。
- **内存**：**【U0 实测】** `windows-latest` 上 `segoeui.ttf` 0.9 MB、`msyh.ttc` 18.8 MB（2 个面）、`malgun.ttf` 12.8 MB，三者都在 `C:\Windows\Fonts`。一律用 `*os.File` 打开后传给 `NewGoTextFaceSource`（集合用 `NewGoTextFaceSourcesFromCollection`），**禁止 `io.ReadAll` / `bytes.Reader`**——实测从字节解析留下的更多（YaHei 94 MB 对 37 MB；面越多差得越大）。但**文件句柄加载留在堆里的也是文件大小的 1.5–2.2 倍**（YaHei 37 MB，Malgun 28 MB，Segoe 2.6 MB），且 `.ttc` 的每个面都会被解析一遍、无法只取一个。所以**一次只常驻界面语言对应的那一个 CJK 字体**，在后台 goroutine 里加载（YaHei 约 100 ms）。
- **按需加载**：启动只加载界面语言对应的主字体 + 内嵌兜底；其余语言的字体在第一次遇到它们独有的字符时再加载（比如中文界面里出现韩文设备名）。判断用 `unicode.Is(unicode.Hangul, r)`、`unicode.Han` 等，不扫描全文。
- **回退链**（`MultiFace` 取第一个含该字形的字体）：

  | 界面语言 | 回退链 |
  |---|---|
  | 简体中文 | YaHei UI → Segoe UI → Malgun Gothic → Go Regular |
  | English | Segoe UI → YaHei UI → Malgun Gothic → Go Regular |
  | 한국어 | Malgun Gothic → Segoe UI → YaHei UI → Go Regular |

  汉字的字形由字体决定，所以韩文界面里偶尔出现的汉字优先用 Malgun 的字形。
- **图标不依赖字体符号**：✓ ⋯ ● ⟳ 之类在不同字体里有无、宽度都不一样。所有图标都是矢量图集，文字里不出现符号字形。
- 字体缺失（精简版 Windows）：回退链自动落到内嵌字体，日志写一行原因；英文界面必须始终可用。

## 5. 设计原则：以远程使用效率为先

### 5.1 原则

| # | 原则 | 含义 |
|---|---|---|
| P1 | **画面第一** | 会话视图里 UI 占用的像素趋近于零：工具条自动隐藏，常驻信息只有一个角标 |
| P2 | **键盘第一** | 所有操作都能只用键盘完成；高频操作有单一快捷键；会话里的 UI 快捷键不与远端冲突 |
| P3 | **状态永远可见且可信** | 连接、主机核对、模式、延迟一眼可见；危险状态（开放模式、未验证的控制者）用红色并**持续**可见，托盘图标也变 |
| P4 | **失败可恢复** | 断线保留最后一帧并可一键 / 自动重连；卡键一键释放；任何错误卡片都带下一步动作 |
| P5 | **能力驱动** | 控件只在对方真的支持时出现；老版本主机上不出现、不报错、更不会因为发了它不认识的消息而断会话 |
| P6 | **安全默认、危险方向要确认** | 严格模式是默认；切到开放需要二次确认；切回严格立即生效 |
| P7 | **三语是一等公民** | 句子不拼接；布局不假设英文宽度；输入法可用 |
| P8 | **空闲零开销** | 没变化就不画、不分配 |

### 5.2 使用场景驱动的设计

| # | 场景 | 设计 | 是否需要后端改动（详见第 10 节） |
|---|---|---|---|
| 1 | 每天连同一台电脑 | 启动即聚焦"快速连接"，上次连接的地址已填好，Enter 连接；已保存设备按最近使用排序，可置顶、可搜索 | 无 |
| 2 | 同时盯多台（车间工控） | 标签编号 + 状态点 + 延迟；`Ctrl+Alt+1…9` 直达；后台标签保持连接；某台断线时标签变色并闪一次 | 无 |
| 3 | 长时间操作远程桌面 | 键盘原样转发；修饰键状态角标（Ctrl / Alt / Shift / Win 按住时亮）；一键释放全部按键；"适应窗口 / 100%" 两种显示（100% 时文字不被缩放糊掉）；全屏；光标捕获 | 无（Ebiten 现有 API） |
| 4 | 网络不稳 | 常驻 RTT / 帧率；断线后保留最后一帧（变暗）并自动重连，**仅对网络类错误**；被主机拒绝、撤销、切换严格模式、身份变化一律不重连，直接给出说明卡片 | 小：重连逻辑 |
| 5 | 往远程输入中文 / 韩文 | "发送文本"框：本地输入法打字，回车后以 Unicode 注入到远端，**不依赖远端的输入法状态**；韩文用户另有 [한/영] [한자] 按钮 | 发送文本依赖路线图阶段 2/3（`MsgText` 与能力协商） |
| 6 | 被控端值守 | 一眼看到：谁在控制、是否已验证、当前模式；一键断开控制者；配对码大字显示；开放模式时整个窗口顶部有红色常驻横幅 | 无 |
| 7 | 排错 | 统计覆盖层（RTT、帧率、码率、被取消的帧）；"复制诊断信息"（版本、系统、语言、地址、ID、模式、最近 50 行日志，不含任何密码） | 小：计数器 |
| 8 | 演示 / 全屏值守 | 全屏 + 工具条自动隐藏；鼠标顶边出现；`Ctrl+Alt+F` 退出 | 无 |

### 5.3 快捷键

会话里，下表所有 `Ctrl+Alt+…` 组合都由查看器拦截，**不转发给远端**（现有行为，现有两个已经在用）。

| 快捷键 | 动作 | 状态 |
|---|---|---|
| `Ctrl+Alt+Q` | 关闭当前会话 | 现有 |
| `Ctrl+Alt+←` / `→` | 上一个 / 下一个标签 | 现有 |

- **发送文本**：工具条下方展开一行输入框（用 `exp/textinput`，候选窗跟随光标），回车后把提交的文本以 Unicode 注入到远端，然后清空；不保存历史。**主机不声明支持该能力时，按钮置灰并说明原因**（P5）。

  - 断线重连中：最后一帧变暗，叠一张"重连中…(3) [停止]"的小卡片。
  - 失败：原因（沿用 `describe()` 的文案，转成字符串键）+ [重试] [关闭]。
  - 被拒绝 / 被撤销 / 主机已切到严格模式 / 身份变化：**不自动重连**，说明如何处理（比如配对码在哪里看）。

## 8. 多语言：简体中文 / English / 한국어

### 8.1 范围与选择

- 三种界面语言：简体中文（`zh-Hans`）、English（`en`）、한국어（`ko`）。
- 默认**跟随 Windows 界面语言**（`GetUserPreferredUILanguages` 的第一个匹配项）；匹配不上用 English。设置里可手动覆盖，存 `settings.json` 的 `lang`（`auto` / `zh-Hans` / `en` / `ko`）。切换**立即生效、不重启**：重建文本布局缓存和字体回退链。
- 繁体中文系统（`zh-TW` / `zh-HK` / `zh-MO`）暂时落到简体中文，直到有人需要再加一张表【提议】。

### 8.2 字符串表

- 每种语言一个 Go 文件（`en.go`、`zh.go`、`ko.go`），键是类型化常量，值是模板字符串，编译进 exe。三种语言合计预计 < 50 KB【推断】。
- **占位符一律具名**（`{name}`、`{count}`），不用 `%s` 这种位置参数。韩文是"主语—宾语—谓语"语序，和英文不同，必须允许译者调整占位符顺序。
- **不拼接句子**：整句是一个键。韩文助词（은/는、이/가、을/를）随前一个词的尾音变化，所以不写"{name}은(는)"这种要靠变量内容决定助词的句子；把变量放在不需要助词的位置（如"기기: {name}"）。
- **复数**：只有英文需要（1 device / N devices）。每个计数相关的文案有 `one` / `other` 两个键，中文、韩文的两个值相同。
- **日期时间**：绝对时间用各语言一致的数字格式 `2026-10-28 09:30`；相对时间用键（今天 / 昨天 / N 天前）。
- **日志和诊断信息保持英文**（给排查问题的人看）；日志查看器的界面外壳翻译。
- **错误信息**：`describe()` 里现有的英文句子全部转成键；来自 Go 或 Windows 的底层错误原文放进"详情"，不翻译。

### 8.3 排版与布局规则

- **不假设英文宽度**：韩文每个音节占一个全角宽度，同样意思的句子可能比英文宽 1.2–1.6 倍【推断，U1 用真实字体量】。按钮宽度 = 文字宽度 + 内边距，设最小宽度，不设固定宽度。
- **断行**：用 UAX#14（`segmenter.LineIterator`）取代现在只认空白的 `Wrap`，中文无空格句子才能正确换行；**截断**按字素簇（`GraphemeIterator`）而不是 rune。
- **行高 / 字号**：见第 6 节（CJK 行高 1.5，最小字号 13）。
- **最坏情况**：加一个伪语言 `xx`（每个字符串放大 1.6 倍并混入中日韩字符），进截图测试，任何控件被截断、重叠都要报错。

### 8.4 输入

| 场景 | 做法 |
|---|---|
| 本地输入框（设备名、地址、搜索） | 用 `exp/textinput.Composer`：预编辑文本画在光标处（下划线），`CaretBounds` 让候选窗跟随；提交文本写入缓冲。**输入框获得焦点时才启用 IME，失焦即关闭** |
| 密码、配对码 | 只接受直接键入和粘贴，不启用 IME |
| 会话中 | 本地 IME **保持关闭**（Ebiten 默认就是关的），物理按键原样转发；远端用什么输入法、处于什么状态由远端决定 |
| 往远端输入非 ASCII 文字 | 两条路：① 在远端自己的输入法里打字（按键转发）；② 工具条的"发送文本"（Unicode 直接注入，不依赖远端输入法状态） |

`exp/textinput` 是实验性 API，所有调用集中在**一个适配文件**里，Ebiten 升级时只改这里（第 11 节）。

## 9. 渲染与代码架构

### 9.1 包划分

```
internal/ui/
  theme/    设计令牌（颜色、间距、圆角、字号），深浅两套；纯数据，可单测
  i18n/     字符串表（en、zh、ko）、语言选择、具名占位符、复数；纯 Go，可单测
  text/     字体定位与按需加载、回退链、UAX#14 断行、字素簇截断、文本布局缓存、textinput 适配器
  gfx/      着色器（SDF 圆角矩形 / 阴影 / 描边）、矢量图标图集、DPI 缩放
  layout/   行 / 列 / 间距 / 对齐 / flex 增长 / 最小最大尺寸；纯 Go，不依赖 GPU，可单测
  widget/   Button、Chip、Card、Segmented、TextField、List、Toast、Modal、Tooltip
  screen/   devices、thishost、session、settings、logs
cmd/go-nx/  只做接线：把主机状态、会话、更新器接到 screen
```

现有的 `internal/ui` 在 U3 达到功能对等之前保留；对等后删除，不长期并存。**`i18n` 和 `text` 放在最前面（U1）**：从第一个控件起就用字符串键，比事后改造便宜得多。

### 9.2 渲染模型：保留树 + 脏标记 + 缓存纹理

- 控件树是**保留式**的，状态变化（数据变化、悬停、焦点、动画帧、语言切换）才标脏。
- 布局只在尺寸或内容变化时重算，结果缓存；绘制命令只在脏时重新生成。
- UI 画到一张**离屏纹理**（UI 层）。没有脏区域时，会话视图每帧只做两次 `DrawImage`：远程画面、UI 层。
- 动画由全局调度器登记：存在活动动画时每帧调度，否则不调度。
- 失效 → 调度：`Invalidate()` 调用 `ebiten.ScheduleFrame()`（见 4.2 的验证要求和降级方案）。

### 9.3 远程画面路径的改进

- 现在每个 tile 在 CPU 上做 BGRA→RGBA（`bgraToRGBA`）。改成把 BGRA 原样上传，由一个 Kage 着色器在采样时交换通道并把 alpha 置 1。省掉 CPU 一遍遍历，也让颜色契约集中在一个地方。
- 契约测试沿用已有思路：红 / 绿 / 蓝 / 不对称色条 + alpha≠255 的金样，在着色器路径上重新断言。

### 9.4 文本

- `Wrap`、`Truncate`、`Width` 的结果按（字符串、字号、最大宽度、语言）缓存，字符串不变就不重排。
- glyph 栅格化由 Ebiten 内部图集缓存；我们只控制"哪些字符串被画"。
- 字体按 4.3 的策略定位、按需打开，文件句柄保持打开直到进程结束。

### 9.5 DPI 与缩放

- 所有布局以逻辑像素定义；字体大小、图标图集、阴影模糊半径都乘以缩放系数。
- 缩放系数变化（拖到另一个显示器）时重建图标图集并整树标脏。
- 测试矩阵：100% / 125% / 150% / 200%，各截一张图。

### 9.6 测试

- `layout`、`theme`、`i18n`、命中测试、焦点顺序：纯 Go 单测，Linux 上就能跑。
- 截图比对：沿用 `tools/uipreview`。CI 的 Linux 作业需要软件 GL（`xvfb-run` + Mesa），**U1 里验证**，不行就把截图测试放到 `windows-latest`。
- 性能：`testing.B` 跑布局和一帧绘制，进 CI 门槛（第 3 节）。
- 行为：每个原有功能在新界面里一一对应，沿用已有的核心单测，不重写业务逻辑。

## 11. 风险与限制

| 风险 | 影响 | 缓解 |
|---|---|---|
| 按需渲染用的 `FPSModeVsyncOffMinimum` 已弃用 | 未来 Ebiten 版本可能移除 | **U0 已验证在 v2.10.5 上两平台都正常**；降级方案是低 TPS + 跳过 `Draw`（已验证可用，空闲略高）；把调度封装在一处 |
| `exp/textinput` 是实验性 API | Ebiten 升级时可能改动 | 所有调用集中在 `text/` 的一个适配文件；锁定 Ebiten 版本；退路是只接受已提交字符 + 粘贴 |
| Ebiten 看不到 한/영、한자键 | 韩文用户无法用物理键切换远端输入法 | **U0 已证实**：注入 VK_HANGUL / VK_HANJA 在 Ebiten 里没有任何键事件也没有字符。工具条按钮发送 VK；"发送文本"绕开输入法；经现有注入路径能否切换远端输入法需装有韩文输入法的远端（H29，用户自行执行） |
| 韩文输入法的实测需要在 PC 上添加韩文输入法 | 会改动系统设置 | 标为"用户自行择机执行"（⚠），不由自动流程做 |
| Ebiten 源码里没有 UI Automation / `WM_GETOBJECT` | 屏幕阅读器读不到界面 | 明确写进已知限制；用键盘导航、焦点环、高对比度主题弥补；这是方案 D 的主要收益点 |
| 自研控件长期维护成本 | 每加一种控件都要自己做 | 控件集刻意保持小（9.1 列的就是全部） |
| 着色器在老 GPU / 远程桌面会话下失败 | 圆角和阴影不显示或窗口异常 | **U0 已在 `windows-latest` 的 DirectX 软件渲染（WARP）和 Linux/Mesa 上验证**：与公式逐像素比较最大差 1/255；真实老 GPU 和远程桌面会话待验证，同时准备不用着色器的九宫格圆角位图作为降级 |
| 系统字体缺失（精简版 Windows） | CJK 显示缺字 | 回退到内嵌字体并记日志；英文界面始终可用 |
| 字体文件很大 | 内存占用、启动变慢 | **U0 实测**：YaHei 18.8 MB → 堆里 37 MB，Malgun 12.8 → 28 MB（见 4.3）。一次只常驻界面语言那一个，后台加载；预算已据此修改 |
| 韩文译文质量 | 用词生硬或错误 | 母语者校对是发布门槛，不是可选项 |
| 工作量大 | 与路线图其他阶段竞争 | 分阶段发布，每个阶段独立可用；旧界面保留到对等 |
