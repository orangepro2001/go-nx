# go-nx UI 重设计方案

- 状态：**仅设计，没有任何代码改动**。日期 2026-10-28。
- 依据：仓库现状（`internal/ui`、`cmd/go-nx`）、Ebiten v2.10.5 源码（`~/go/pkg/mod`）、上一轮的验收与路线图。
- 约束来自项目初衷：**少依赖、超高性能**，单个静态 exe，无 cgo。不新增第三方模块。
- 标注说明：**【事实】** 来自代码或 Go 模块缓存里的源码；**【推断】** 是我基于经验的判断，没有在本项目里实测；**【目标】** 是要达到的数字，不是已测得的数字。所有性能数字必须先过 U0 的基线测量才算数。

## 1. 目标与非目标

目标：

1. 外观对齐现代远程控制应用的共同模式：深色为主、卡片化、单一强调色、清晰的连接状态、会话中不遮画面的悬浮工具条。
2. 空闲时几乎不占 CPU/GPU；会话中 UI 不增加每帧工作量。
3. 中英文都能正常显示和输入。
4. 把现在散落的绝对坐标常量换成可缩放的布局，支持 100%–200% 显示缩放。
5. 每个界面状态都能在没有 Windows 的 CI 上截图比对。

非目标：

- 不引入 Web 技术栈（WebView2、HTML/CSS、Electron）。
- 不改线上协议，也不新增远控功能；UI 需要的后端改动在第 8 节单列。
- 不在这份文档里承诺屏幕阅读器支持（见第 9 节的限制）。

## 2. 现状盘点【事实】

| 项 | 现状 |
|---|---|
| 渲染栈 | Ebiten v2.10.5（Windows 上链接了 DirectX 和 OpenGL 两个后端）+ `text/v2` + go-text/typesetting |
| UI 代码 | `internal/ui`：`home.go` 342 行、`tabbar.go` 102、`ui.go` 109、`logview.go` 54，加上 `cmd/go-nx/viewer_windows.go` 323 行。全部是矩形 `Fill` + 文字，**没有**圆角、阴影、图标、动画、主题 |
| 布局 | 固定 1180×700 的绝对坐标常量（`chkY`、`actionY`、`listX` 等）；窗口大小固定，靠 `DeviceScaleFactor` 整体放大 |
| 字体 | 内嵌 Go Regular（`goregular.TTF`），**只含拉丁字母——现在界面无法显示中文** |
| 帧循环 | 窗口可见时固定 60 TPS 持续重绘，隐藏到托盘时降到 5 TPS（`activeTPS`/`idleTPS`）。没有"没变化就不画" |
| 文本输入 | 只有 `ebiten.AppendInputChars`；没有 IME 组合态，没有光标位置同步 |
| 远程画面 | tile 补丁写入一张 `ebiten.Image`，`DrawImage` 缩放绘制；BGRA→RGBA 的通道交换在 **CPU** 上逐 tile 做（`bgraToRGBA`） |
| 依赖 | `go.mod` 直接依赖 4 个模块：ebiten、systray、quic-go、x/image；整个模块图 39 个。exe 约 19 MB（大头是 QUIC 和 Ebiten） |

结论：渲染栈本身（GPU 纹理、DrawImage、Kage 着色器）足够好，缺的是**一套 UI 工具箱**和**按需渲染**，不是换引擎。

## 3. 性能预算【目标，待 U0 基线验证】

| 场景 | 预算 | 怎么测 |
|---|---|---|
| 窗口可见、无动画、无会话（空闲） | 单核 CPU < 0.3%，不提交 GPU 帧 | Windows 性能计数器 / 任务管理器采样 60 s |
| 会话中画面静止 | 无输入、无 tile 更新时不提交帧 | 帧计数器（`ebiten.ActualFPS` 的替代：自己数 `Draw` 次数） |
| 会话中画面更新 | 每帧最多 2 次 `DrawImage`（远程画面 + 缓存好的 UI 叠加层）；一个 64×64 tile 的上传 + 绘制 ≤ 0.2 ms | `testing.B` + 合成源 |
| 主页一帧 CPU 提交时间 | p99 ≤ 2 ms（1080p，100% 缩放） | `testing.B`，N=1000 帧 |
| UI 响应 | 点击到画面变化 ≤ 1 帧（16.7 ms @60Hz） | 输入时间戳到 `Draw` 完成 |
| 启动到第一帧 | ≤ 300 ms（现有日志已记录 `first Draw`，先量基线） | `go-nx.log` 的 startup 行 |
| 常驻内存（空闲） | ≤ 60 MB，glyph/文本布局缓存有上限 | 任务管理器私有工作集 |
| 二进制增量 | UI 相关 ≤ 1.5 MB（字体不内嵌） | `ls -l build/go-nx.exe` 对比 |
| 新增第三方模块 | 0 | `go.mod` diff |

预算写进 CI：布局和绘制的 benchmark 作为回归门槛，超出基线 20% 就失败（U6）。

## 4. 技术栈决策

### 4.1 选项评估

| 选项 | 新增依赖 | 性能 | 美观上限 | CJK / IME | 结论 |
|---|---|---|---|---|---|
| **A. 继续用 Ebiten，自研极简 UI 层**（推荐） | 0 | 好：远程画面本来就在 GPU 纹理上；UI 叠加层缓存成一张纹理 | 高：自己控制着色器，圆角 / 阴影 / 渐变都能做 | 字体可用系统字体；IME 组合态需要验证（见 U0） | **选它** |
| B. Gio | 新模块 `gioui.org` 及其依赖 | 好【推断】 | 高 | 文本栈同为 go-text【推断】 | 需要替换整个窗口 / 渲染层，远程画面局部上传模型要重做；增加依赖，收益不抵成本 |
| C. Wails / WebView2 | WebView2 运行时 + 前端工具链 | 内存和启动都重 | 高 | 好 | 与"少依赖、超高性能"直接冲突，本机 `win32-theme-for-wails` 的试验也说明这条路的取舍 |
| D. 原生 Win32 + Direct2D/DirectWrite（纯 syscall，无 cgo） | 0 第三方，但要手写 COM 调用 | 最好 | 高，系统字体 / IME / 无障碍最原生 | 最好 | 工作量最大，没有现成的纯 Go 绑定；**作为长期备选**，如果 U0 发现 Ebiten 的 IME 或无障碍无法接受再启动 |
| E. libw2k（Win2000 风格） | — | 好 | 风格不符 | — | 不选 |
| F. Fyne | 多，且常带 cgo | 一般【推断】 | 中 | — | 不选 |

B–F 的判断【推断】，没有在本项目里做过基准；只有 A 的依据来自本仓库代码和 Ebiten 源码。

### 4.2 在 Ebiten 里要用到的能力【事实：已在 v2.10.5 源码里核对存在】

- **Kage 着色器**：`ebiten.NewShader`、`DrawRectShader`、`DrawTrianglesShader`。用一个 SDF 着色器同时画圆角填充、描边和柔和阴影，相同着色器 + 相同纹理的绘制会被 Ebiten 合批。
- **多字体回退**：`text/v2` 的 `MultiFace`（Latin → CJK 回退）；`NewGoTextFaceSourcesFromCollection` 能读 `.ttc` 字体集合（`msyh.ttc` 就是）。
- **矢量路径**：`ebiten/vector` 包，用来把图标路径栅格化。
- **按需渲染**：`ebiten.ScheduleFrame()` 配合 `FPSModeVsyncOffMinimum`。**注意：这个模式在 v2.5 起被标为 Deprecated**，官方推荐的替代是 `SetScreenClearedEveryFrame(false)` + 没变化就跳过 `Draw`（`examples/skipdraw`）。后者省 GPU 但 `Update` 仍按 TPS 运行。所以 U0 必须验证两件事：（a）弃用的模式在 v2.10.5 + Windows 上是否仍然正常工作；（b）不行时，把 TPS 降到 5–10、空闲时跳过 `Draw` 的方案能否达到预算。

### 4.3 字体策略

- **不内嵌 CJK 字体**（会让 exe 增加几 MB，违背初衷）。运行时从 `C:\Windows\Fonts` 读取：首选 `Segoe UI Variable` / `Segoe UI`（拉丁），CJK 用 `Microsoft YaHei UI`（`msyh.ttc`）；用 `MultiFace` 做回退链，最后兜底仍是已内嵌的 Go Regular。
- 字重：用同一字体族的 Regular 和 Semibold 两个文件；找不到 Semibold 时用 Regular 加大字号来表现层级。
- 字体读取失败不能崩：回退到内嵌字体，界面里的中文会显示缺字，并在日志里写一行原因。
- 字体文件来自系统，**不随程序分发**，不涉及字体授权问题。

## 5. 视觉设计语言

### 5.1 对齐原则

我没有对照任何具体产品的截图；下面是对"现代远程控制应用"共同模式的归纳，用来定方向，不是复刻某一款：

- 深色为主，背景低饱和，只有**一个**强调色；状态用色点 + 文字芯片（chip），不靠整块变色。
- 内容放进圆角卡片，卡片之间用留白和极淡的边框分层，而不是粗线条。
- 设备以卡片网格呈现，每张卡片有名称、地址、状态和一个主按钮。
- 连接是一个明确的状态机：连接中 → 核对主机 → 已连接 / 失败，每一步都有完整的卡片说明，而不是一行红字。
- 会话中画面铺满窗口；工具条悬浮在顶部居中，几秒无操作自动隐藏。
- 关键数字（配对码、主机 ID）用大号等宽字体显示。
- 动效克制：120–200 ms 的缓动，只用于状态变化。

需要你确认：如果你有想对齐的具体产品，请给我名称或截图，我据此调整第 5 节和第 6 节。

### 5.2 设计令牌（token）

尺寸全部用**逻辑像素**，绘制时乘以显示缩放系数（`DeviceScaleFactor`）。间距遵循 4 px 网格。

| 类别 | 值 |
|---|---|
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 |
| 圆角 | 小 6（芯片、输入框）、中 10（卡片、按钮）、大 16（对话框） |
| 字号 | 12 说明、14 正文、16 小标题、20 标题、28 大数字；配对码 / ID 用 32 等宽 |
| 控件高度 | 按钮 / 输入框 36，列表行 48；最小可点击区域 32×32 |
| 阴影 | 卡片：y+2、模糊 8、不透明度 18%；对话框：y+8、模糊 24、不透明度 32% |
| 动画 | 悬停 / 按下 120 ms，面板出现 180 ms，缓动 easeOutCubic；尊重系统"减少动画"设置 |

配色（默认深色，跟随 Windows 应用主题切换）。**对比度已用脚本算过**，文字 / 背景均 ≥ 4.5:1（WCAG AA）：

| surface 卡片 | `#171B23` | `#FFFFFF` | — |
| surface-2 悬停 / 输入框 | `#1F2430` | `#EEF1F6` | — |
| border | `#2B3240` | `#D5DBE6` | — |
| text | `#E8ECF3` | `#161B26` | 14.56（surface） |

| warn 开放模式 / 注意 | `#F5A524` | `#B45309` | 8.45 / 5.02 |
| bad 错误 / 危险 | `#F0524D` | `#C62828` | 4.94 / 5.62 |

- **设置**：外观（跟随系统 / 深色 / 浅色）、语言（跟随系统 / 中文 / English）、网络（监听地址，对应 `-listen`）、更新（当前版本、检查按钮、上次检查时间）。

- **更新**：侧栏底部常驻版本号和更新状态；有更新时出现强调色圆点。沿用现在的两次点击重启确认。

### 6.6 其他

- **通知（toast）**：右下角，非阻塞，4 秒消失，用于"已断开 N 个未验证的会话""已忘记设备"等现在写在消息行里的反馈。

## 7. 渲染与代码架构

### 7.1 包划分

```
internal/ui/
  theme/    设计令牌（颜色、间距、圆角、字号），深浅两套；纯数据，可单测
  gfx/      着色器（SDF 圆角矩形 / 阴影 / 描边）、矢量图标图集、文本布局缓存、DPI 缩放
  layout/   行 / 列 / 间距 / 对齐 / flex 增长 / 最小最大尺寸；纯 Go，不依赖 GPU，可单测
  widget/   Button、Chip、Card、Segmented、TextField、List、Toast、Modal、Tooltip
  screen/   devices、thishost、session、settings、logs
  i18n/     字符串表（en、zh-CN），按系统语言选择
cmd/go-nx/  只做接线：把主机状态、会话、更新器接到 screen
```

现有的 `internal/ui` 在 U3 达到功能对等之前保留；对等后删除，不长期并存。

### 7.2 渲染模型：保留树 + 脏标记 + 缓存纹理

- 控件树是**保留式**的，状态变化（数据变化、悬停、焦点、动画帧）才标脏。
- 布局只在尺寸或内容变化时重算，结果缓存；绘制命令只在脏时重新生成。
- UI 画到一张**离屏纹理**（UI 层）。没有脏区域时，会话视图每帧只做两次 `DrawImage`：远程画面、UI 层。
- 动画由全局调度器登记：存在活动动画时每帧调度，否则不调度。
- 失效 → 调度：`Invalidate()` 调用 `ebiten.ScheduleFrame()`（见 4.2 的验证要求和降级方案）。

### 7.3 远程画面路径的改进

- 现在每个 tile 在 CPU 上做 BGRA→RGBA（`bgraToRGBA`）。改成把 BGRA 原样上传，由一个 Kage 着色器在采样时交换通道并把 alpha 置 1。省掉 CPU 一遍遍历，也让颜色契约集中在一个地方。
- 契约测试沿用已有思路：红 / 绿 / 蓝 / 不对称色条 + alpha≠255 的金样，在着色器路径上重新断言。

### 7.4 文本

- `Wrap`、`Truncate`、`Width` 的结果按（字符串、字号、最大宽度）缓存，字符串不变就不重排。
- glyph 栅格化由 Ebiten 内部图集缓存；我们只控制"哪些字符串被画"。
- 文本输入框：先支持已提交字符（`AppendInputChars`）；IME 组合态是否可用由 U0 验证，不可用就在设置里提示"中文输入请粘贴"，并把 D 方案列为后续。

### 7.5 DPI 与缩放

- 所有布局以逻辑像素定义；字体大小、图标图集、阴影模糊半径都乘以缩放系数。
- 缩放系数变化（拖到另一个显示器）时重建图标图集并整树标脏。
- 测试矩阵：100% / 125% / 150% / 200%，各截一张图。

### 7.6 测试

- `layout`、`theme`、命中测试、焦点顺序：纯 Go 单测，Linux 上就能跑。
- 截图比对：沿用 `tools/uipreview` 的做法（用虚拟显示渲染 PNG），每个界面状态一张金样，带容差比较。CI 的 Linux 作业需要加软件 GL（`xvfb-run` + Mesa），**这一点要在 U1 验证**，不行就把截图测试放到 `windows-latest`。
- 性能：`testing.B` 跑布局和一帧绘制，进 CI 门槛（第 3 节）。
- 行为：每个原有功能在新界面里一一对应，沿用已有的核心单测，不重写业务逻辑。

## 8. 界面需要、但现在后端没有的东西

## 9. 风险与限制

| 风险 | 影响 | 缓解 |
|---|---|---|
| 按需渲染用的 `FPSModeVsyncOffMinimum` 已弃用 | 未来 Ebiten 版本可能移除；当前版本是否仍然生效待验证 | U0 先验证；降级方案是低 TPS + 跳过 `Draw`；把调度封装在一处，便于替换 |
| Ebiten 没有 IME 组合态 API | 中文输入时候选框位置不对、无法预编辑 | U0 验证提交字符能否到达；不行则粘贴 + 后续评估 D 方案 |
| Ebiten 不暴露 UI Automation | 屏幕阅读器读不到界面 | 明确写进"已知限制"；用键盘导航、焦点环、高对比度主题弥补；这是 D 方案的主要收益点 |
| 自研控件长期维护成本 | 每加一种控件都要自己做 | 控件集刻意保持小（第 7.1 列的就是全部），布局和令牌集中，避免各处散写 |
| 着色器在老 GPU / 远程桌面会话下失败 | 圆角和阴影不显示或整个窗口异常 | 同时准备不用着色器的九宫格圆角位图作为降级；在 U0 里用 `windows-latest` 的软件渲染器跑一遍 |
| 系统字体缺失（精简版 Windows） | 中文显示缺字 | 回退到内嵌字体并记日志；界面文案同时保证英文可用 |
| 工作量大 | 与路线图其他阶段竞争 | 分阶段发布，每个阶段独立可用；旧界面保留到对等 |

## 10. 迁移计划

每个阶段改变行为时都按约定 `scripts/ship.sh` 发布一个新版本；纯文档 / 测试不发。

| 阶段 | 内容 | 退出条件 |
|---|---|---|
| **U0 基线与技术验证**（不改界面） | 测空闲 CPU、首帧时间、内存、tile 上传耗时（Windows，用户的 PC + `windows-latest`）；验证 `ScheduleFrame` 在 v2.10.5 上是否按预期；验证系统字体读取和中文渲染；验证 SDF 着色器在 DirectX 后端的表现；验证提交字符 / IME；验证 Linux CI 上截图可行性。输出 `docs/ui-baseline.md` | 每一项有数字或明确结论；任何一项不通过，先改方案再往下 |
| **U1 令牌与绘制原语** | `theme`、`gfx`（圆角 / 阴影着色器、图标图集、文本缓存）、缩放；`tools/uipreview` 生成第一批金样 | 原语的截图测试通过；绘制基准达标 |
| **U2 布局与控件** | `layout`、`widget`、焦点与键盘导航、命中测试 | 纯 Go 单测全绿；控件截图金样 |
| **U3 功能对等** | 本机、设备、首次连接核对页，一一对应现有行为；删除旧 `internal/ui`（可保留一个版本的 `-classic-ui` 开关） | 现有 H13–H19 的人工清单在新界面上全部通过 |
| **U4 会话视图** | 悬浮工具条、标签条、连接状态卡片、着色器通道交换、帧率芯片 | 会话预算达标；颜色契约测试通过 |
| **U5 设置与体验** | 设置页、i18n、跟随系统主题、toast、托盘图标状态、逐设备撤销 | 中英文截图齐全；系统主题切换生效 |
| **U6 打磨与门槛** | 动画、150%/200% 缩放矩阵、键盘全流程、高对比度、性能回归进 CI | 第 3 节预算全部有测量值并达标 |
